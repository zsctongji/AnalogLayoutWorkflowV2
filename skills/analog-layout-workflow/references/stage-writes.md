# Batch writes at the end of each skill stage

Perform planning, candidate search, module grouping, ABBA arrangement, shared-chain positioning and contact/guard-ring geometry checks in memory or local files. Reads of saved schematics, live geometry and qualification records are allowed during the stage; do not create/save an OA cell for each candidate. Reuse existing parameter-matched PCell measurements. Required new probes belong in controlled writes at stage end; if the adapter cannot support that boundary, first output candidates and required capabilities.

First follow [save-policy.md](save-policy.md): one working layout by default, with stage archives only at explicit user request. At the end of each implementation stage, execute: fresh read-only checks → controlled in-place transaction on the current working layout → one batch application of all edits → complete unsaved-geometry readback and verification → one save → independent post-save readback. Clone only for initial target creation or explicit archives; cloning, object creation and saving also occur at stage end. One batch means one CAD call processing the complete edit list, rather than creation of one database object. Keep all stages serial.

`adapter_runtime.execute` must call `apply_batch(tx, edits)` once, with no per-object fallback. `VirtuosoBackend.apply_batch` first validates all ids, owner/net/LPP, old-object hashes and geometry/grid locally, then applies all owned rectangles using one native data list and loop. Do not split into batches of 40/35 objects or recapture the entire layout per object. `read` is always read-only and must not flush queued writes. The PCell importer combines all instances and D/net annotations in one transaction; any object/annotation failure prevents saving.

Preserve owner/id, all copies/parameters/nets, protected objects and mirror/sharing checks. Discard unsaved edits when actual verification fails. If readback fails after a successful save, or save status is unknown, retain the target for diagnosis; do not repeat writes or claim rollback. Code changes invalidate old adapter qualification; updating hashes alone cannot impersonate renewed live qualification. Record actual CAD batch-call/save counts or command logs. Passing offline tests establishes only the behavior covered by those tests.

Auxiliary `conopc` for newly constructed contacts/guard rings may be omitted; handoff `include_conopc` defaults to false. The current generators can enable it with `--include-conopc`. Native-via or internal PCell geometry remains PDK-defined. Retain related violations/waivers in actual foundry DRC reports; this generation preference is not a process-rule compliance conclusion.
