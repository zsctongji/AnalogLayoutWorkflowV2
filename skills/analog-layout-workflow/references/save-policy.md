# One layout, saved at each stage

**Default to `save_policy.mode: single-layout`. Unless the user explicitly requests stage archives, use one explicitly identified `lib/cell/layout` continuously from initial placement through diffusion sharing, gate access, guard rings, macro adjustment, routing and DRC/LVS repairs. Use `staged` only when the user explicitly requests preserved stage layouts, stage copies or Save As to a specified target.**

- Initial working-layout creation may copy the complete user-specified source once; reuse that working target afterward. Verify actual identity/save status of existing targets first. Continuing work reuses the confirmed current target without asking for cell names at every stage.
- Ordinary requests to continue or execute the next stage do not request stage archives. Permission to use a scratch naming prefix also does not require stage archives; use one layout when archives were not requested.
- `single-layout` does not mean saving only at the end. At each stage end, apply one batch, verify complete unsaved geometry, save once and perform independent post-save readback. Every save of the same cellview creates a new revision/hash; invalidate old evidence by actual dependencies.
- Retain stage JSON, logs, reports, previews and geometry hashes; these are not stage layout archives. Do not automatically create layout cells/views for candidates, failed retries or capability probes.
- Same-target edits require an in-place transaction adapter: check the saved baseline, prohibit mixing user unsaved edits, preserve protected objects/electrical identities and undo this stage's unsaved changes on pre-save failure, restoring the previous saved stage. For unknown save status or post-save verification failures, retain the current target for read-only diagnosis without claiming rollback.
- If a legacy tool supports only absent-target clones or PCell-only reconstruction, adapt/select a qualified in-place transaction. Without that capability, explicitly record `BLOCKED_CAPABILITY` and retain offline candidates. Do not independently switch to multiple archived targets or bypass original geometry/connectivity verification.
- For explicit user `staged` choices, record the original request, target names and archive scope. Only this mode uses absent destinations for stage copies. Changes to default policy do not delete or merge historical scratch cells.

This rule unifies subskill save policies. New-target, absent-target, no-source-overwrite instructions and clone-only adapter boundaries in legacy documents apply only to initial working-target creation, explicit Save As/stage archives, or the corresponding legacy adapter itself. They cannot override default same-target progression. Preserve the source schematic/PDK and unrelated designs; in-place updates to the current working layout are not unauthorized overwrites of another design. A documented policy does not establish in-place transaction qualification for legacy adapters.
